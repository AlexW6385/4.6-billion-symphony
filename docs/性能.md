# 性能记录

- 发布用压缩版：`npm run build:min`（esbuild 压缩主脚本和数据，源文件不动）。
- 卡顿优化：隐藏分支跳过矩阵更新（每帧轮流做 1/30 全量）；精灵合批只在场景有新增时重扫；遮挡切除射线先做包围球预筛；大网格（≥3000 三角）用自建包围盒树求交，进入世界后空闲时预建；番外卷轴放置去掉 O(n²)；点光源改为每个世界 2 盏固定灯池，避免灯数变化导致所有着色器重编译；虚空星球贴图先画 1/4 尺寸，空闲时分行补画全尺寸。
- 地被（草丛、石头）重算分约 5 帧完成，颜色解析加缓存；像素比上限 1.5，泛光按屏幕点分辨率算（高分屏省 GPU）。
- 跟随移动目标时，每 0.35 秒的视线检测只测可见实体网格；遮挡切除搜索改为生成器分 5 帧完成。
- 省电：手机上阅读器或图书馆打开时，3D 画面完全暂停；大屏上面板打开时降到 24 帧；15 秒没有操作、画面也没在动时降到 30 帧。降帧期间不触发自动降画质。
- 所有世界共用一套灯光布局（两盏平行光、一盏半球光、两盏点光灯池、同一种雾）：three.js 按灯光数量和雾的种类生成着色器，原来每进一个新世界要新编 18–49 个程序，现在去过一个星球、一个非星球世界之后，每次切换只新编 1–9 个（游遍全部世界 314 → 180 个）。只有星球的太阳投影子，所以星球之间、其他世界之间各自共用。
- 不再提前建造世界：建造是一整块 0.3–2 秒的脚本，没有哪个时刻不被感觉到（图书馆或阅读器打开时会冻住它们的滚动；在外面会冻住画面）。第一次去一个世界在「正在前往」的遮罩下建造；之后只分片编新着色器。
- 第一次进入后，新世界先在暗处画两帧（阴影程序、贴图上传），然后才开始淡入，淡入不会卡在半途。
- 每个网格的包围球在进入世界后分片算好；第一次跳词条不再一次算全部（虚空里 140 ms → 20 ms）。按词条找场景里的物体用索引，不再每次遍历整个场景。
- 跳到词条：找清楚视角的搜索不再在点击的那一刻做完。镜头立刻起飞，搜索在之后几帧里分片进行（每片约 3 ms，每条视线一个单位），找到更好的位置时把飞行终点挪过去（飞行刚开始时挪动看不出来）。遮挡物列表也分片收集。点光灯池和阴影的重新扫描分片进行。800 个三角形以上的网格都有射线加速树（空闲时预建）。
- 仍然存在：第一次进入一个世界时遮罩下的建造和编译（约 1–2 秒）。
- (2026-10-26, draw calls) Measured with `tests/calls.cjs`: on a 绒球 meadow every frame drew 1,500 calls and 6 M triangles, and every other frame the shadow map drew nearly the whole visible planet again (1,900 calls, 8.9 M triangles averaged). Three causes, three fixes:
  - Instanced and merged scenery sets cannot be frustum-culled by three.js (an instanced set's bounds are one instance's). Just before a frame is drawn, every culled set whose sphere lies outside the view and outside the column the shadow box casts along the sun is hidden, and shown again after the frame (flight planning and line-of-sight tests still see them).
  - The shadow map only draws sets whose sphere reaches the column of its box.
  - A herd creature less than a few pixels long is neither drawn nor moved; in the open spaces any entry whose radius would be under 1.5 px is hidden (its mote still shows it).
  Meadow: 874 calls / 3.8 M triangles per frame, no heavy shadow frames. Town: 1,262 → 943 calls. Void arrival: about −20 %.
- Parts of a far model that are under a pixel in radius (an eye, a claw, a strut) are not drawn; each model's parts are listed once, biggest first, so the check is a short loop per model. Void arrival 794 → 461 calls, 不可预见之地 411 → 71, 绒球 meadow 874 → 775.
- A herd creature's parts under about two pixels across (legs, eyes, spines of a creature in the middle distance) are not drawn; checked every fourth frame per creature with the same sorted part list as the far models. 绒球 meadow 782 → 566 calls, town 942 → 466 (the 银甲龙 herd alone 330 → 7 at the test size).
- Hover picking is skipped while neither the pointer nor the camera moves (it ran every other frame, a cost on alternate frames), and the hover label's width is read once per change, not every frame (a forced layout).
- Quality steps also react to dropped frames: more than one frame in ten over 26 ms, or under 52 fps, lowers the level; it comes back only when nearly every frame is on time. A steady 45 fps used to keep the best level and judder.
- A view found while the camera is already flying no longer makes it jump: early in the flight the start point moves with the end point so the current pose stays put; later, the flight finishes and one short move follows.

## 工具

- `node tests/perf5.cjs <space>`：每帧 JS 耗时。一次只跑一个，并行跑会出现假的尖峰。
- `node tests/trace1.cjs`：性能采样（环境变量 `ID` `FROM` `N`）。
- `node tests/audit.cjs`：逐个跳到每个词条，检查是否在画面内、是否被遮挡、屏幕上多大。
- `node tests/path.cjs [mob]`：按 DESIGN 的交互路径走一遍（分享链接 → 卡片 → 相关 → 章节 → 返回 → 图书馆 → 阅读器 → 虚空 → 返回），报告每一步的脚本耗时。
- `node tests/switch.cjs`：依次进入每个世界，记录新编着色器数和长帧。
- `node tests/calls.cjs [space,…]`: draw calls and triangles per frame (four frames each, so a heavy shadow frame shows), per space and on two 绒球 views. `BREAK=1` (or 2) also lists what the calls go to.
