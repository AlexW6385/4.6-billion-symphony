# 架构

整个展览馆是一个单页：`src/` 里的文件按 `scripts/order.txt` 的顺序拼起来，就是 `index.html`。除第一个和最后一个外都是 JS 片段，共处一个立即执行函数里，互相直接调用。Three.js r128 从 CDN 加载。

数据单独放在 `data/`，作为普通脚本加载：

| 文件 | 内容 |
|---|---|
| `wiki.js` `wiki3.js` `wiki4.js` | 词条（`window.WIKI`）：名字、分类、所在世界与坐标、时代、简介 `s`、正文 `d`、章节 `ch`、相关词条 `rel`、造型 `k`/`kp` |
| `chapters.js` | 章节索引：只有卷名、章序与章名 |
| `links.js` | 词条之间的连线 |

## 词条造型

- 星球上：`entryModels` 和生物群（herd）。
- 虚空等非星球空间：`placeEntries` 里，`k` 不是 `'none'` 就交给 `makeShape`（专门模型或 `kitShape` 的对应分支）；`k:'none'` 走 `entryShape()`，查 `46_ents.js` 的 `ENT` 表。

## 调试接口

页面暴露 `window.__rq`（`enterSpace(id)`、`CUR`、`ren` 等），测试脚本靠它跳转和检查。

## 约定：不覆盖别的文件里的函数

以前的补丁层（`49c_fixA` … `49q_lean`）靠「先存下旧函数、再给同名变量赋新函数」来改行为，同一个函数最多被改写五次，读代码时找不到真正生效的版本。这些层已经全部并回原处，规则是：

- 顶层函数只声明一次，任何文件都不再给别处的函数名重新赋值（`tests/fingerprint.cjs` 之外，可以用作用域分析检查：没有对顶层函数名的写入）。
- 一个函数需要在别的模块里加一层处理时，写成有名字的阶段，依次调用：原函数叫 `名字Base`，每一层是一个带模块前缀的函数（如 `q3_towerMat`、`q4a_towerMat`），调用上一层；最后一层保留原名。阅读时从原名往回找就是完整的链。
- `SPEC` / `KIND` / `ENT` 每个键只写一次，写在表本身里（`30_creatures.js` / `46_ents.js`），或第一次出现的文件里。
- `getSpace` 是唯一的建造入口，建好后依次做：近处地面、光和空气、柔化、彩蛋。

## 重构验证

- `node tests/fingerprint.cjs out.json`：在虚拟时钟和固定随机数下，记录每个造型、每个世界场景里的每个物体（类型、几何、变换、材质和着色器的哈希）。`--diff a.json b.json` 比较两个构建。只改代码组织、不该改变画面的提交，必须让模型和场景完全一致（`tables` 一栏只是函数源码文本，改名时会变）。
- `node tests/shots.cjs dir`：在 `tests/viewpoints.json` 的固定视点截图；`--diff dirA dirB` 比较。
